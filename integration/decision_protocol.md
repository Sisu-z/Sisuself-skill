# 联合决策协议

本协议是 Sisu 的个人库与认知库共同入口。适用于路线、资源分配、项目、职业、商业及有实质取舍的决策；孤立事实、机械操作不强制加载背景。两库分开维护，联合读取，不合仓、不自动公开、不自动监控聊天。

## 从任何一边进入

- 从 Sisuself 的 `SKILL.md` / `AGENTS.md` 进入，先读本协议及 [manifest.json](manifest.json)。
- 从 cognition-kb 的 `AGENTS.md` / `08_AI知识包/00_AI_GUIDE.md` 进入，也先取本协议；该库的 `_工具/joint_decision.py` 是同一加载器的薄入口。
- 本协议以 Sisuself 当前选定提交为唯一正文；另一库只链接它。每次分别锁定两库 SHA，所有文件按各自 SHA 读取，不假定两库提交同步。
- 不读取未提交工作区内容来冒充已发布版本。联网读取前刷新远端引用；离线运行如实列出快照和未核实项，不改工作区、不强制同步。

## 实际读取

两个仓库位于同级目录时，从 Sisuself 运行：

```sh
python3 scripts/joint_decision.py load --refresh --question '我应先做产品，还是先验证渠道、交付与验收？' --output /tmp/sisu-joint-context.json
```

从 cognition-kb 运行：

```sh
python3 _工具/joint_decision.py load --refresh --question '我应先做产品，还是先验证渠道、交付与验收？' --output /tmp/sisu-joint-context.json
```

不在同级目录时显式传 `--personal-repo` / `--knowledge-repo`。工具仅依赖 Python 标准库和 Git；使用已获授权的仓库副本，不读取 Vault 原始笔记。`--refresh` 仅 fetch，不 pull、checkout、提交或推送。显式 `--personal-ref` / `--knowledge-ref` 用于固定版本复验。

联合上下文包含：问题、路由主题、两库 SHA、所读文件、来源 ID、内容校验、动态状态日期、缺失与警告。`--metadata-only` 去掉正文，适合核验读取清单。完整上下文可能含私有材料，不能提交到公开库或发布；本地临时文件使用后按需要清理。

仅有 HTTP/连接器的 Agent 应执行同等步骤：解析每库当前默认分支 SHA，按 manifest 读同版本文件，查主索引后取命中原文，并列出缺失与状态日期。GitHub 大文件使用 blob/raw/Git clone 路径，不能把 Contents API 空正文当作完整读取。无权限读取私有库时，明确报告联合读取不完整；禁止假称已经调用。

## 将材料用于决策

1. 以当前问题确定目标、资源、硬约束与时间范围。个人背景、历史策略、当下用户纠正分开；不知道的投入、资金和能力不填数。
2. 检查动态状态有效性。超过复查日或战略锁期限的条目只作为历史；本次整理不更新技术路线，也不把旧锁继续生效。需要现状时结合当前会话与实际证据核实。
3. 调相关认知框架与索引命中原文。选方向时读 A1，商业执行读 M0/S/P，个人实践读 B1；学习/生活问题只取适用的方法，框架不适用时明确说明。加载到文件不等于完成推理或证明结论。
4. 区分个人目标与事实前提：框架不能替换用户目标；证据反驳事实假设时说明错误前提，调整实现路径。方法论也需适用条件和反例。
5. 对同源转述、用户吸收后的复述、AI 提炼及两库副本只计一次证据。多个来源说法相同不自动提高可信度，先检查独立性与事实依据。B1 是个人经验/认知整理，部分为外部访谈转述，不整体当原创或多来源验证。
6. 输出有主次的建议：当前目标与约束、适用框架和出处、可比较方案与机会成本、关键反证、下一条能改变判断的证据。外部价格、规则、政策等需要当前核验；本库旧数字不能充当实时事实。

## 反馈回流

反馈先区分“观察/假设”“未采纳建议”“明确决定”“已经行动”“验证有效”。用户明确决定才写决策史；运行样例和测试反馈不能写成真实个人经历。

| 反馈 | 正文归属 | 另一边保留什么 |
|---|---|---|
| 本人的决定、约束、进度和认知变化 | Sisuself 对应 `context` 文件；决策史只追加 | 需要时仅引用决策 ID |
| 可迁移方法、匿名实践案例、框架纠错 | cognition 的正文、来源登记；冲突进待裁决 | Sisuself 留个人适用性和条目链接 |
| 原话、私人细节、第三方信息 | 私有来源；Vault 原文保留 | 只留经过筛选的摘要与来源 ID |

只读加载不触发回写。显式记录反馈时，用同一工具：

```sh
python3 scripts/joint_decision.py feedback --input /tmp/sisu-feedback.json --queue-dir /tmp/sisu-private-feedback
```

输入必须有 `id`、`kind`（decision/observation/correction/method）、`summary`、`event_date`、`source_ids`、`status`（candidate/confirmed）、`scope`（personal/knowledge/both）；修订用 `supersedes` 引用旧 ID。`confirmed` 必须有实际用户确认或核验依据，不能仅因程序字段合法而声称成立。

工具写入显式指定的本地私有待审队列，给出目标库和文件；同 ID 同内容幂等，冲突拒绝，跨库用引用而非复制正文。**入队不是已经更新知识库。** Agent 在当前写入授权下核对来源、去重、隐私和状态，再应用到上述权威正文；方法变动同步来源、冲突及索引。回读修改后确认条目生效，提交并核验远端 SHA。未授权写入或缺权限时保留待审，不自动提交、公开或替用户决定。
